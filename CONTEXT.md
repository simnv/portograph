# portograph — Domain Context

Glossary and invariants for the project. Use these terms exactly; do not drift to synonyms. When a
concept you need is missing here, that is a signal — either you are inventing language the project
does not use, or there is a real gap to record.

`portograph` turns a YAML description of nodes, ports, links and groups into a laid-out diagram
(SVG), choosing the drawing technique per part of the diagram so the result reads like an engineer
drew it. Network diagrams first; software architecture and electrical panels next.

For short definitions grouped by topic, see [GLOSSARY.md](GLOSSARY.md).
This document keeps the detailed vocabulary, invariants and geometry rules.

---

## Core vocabulary

| Term | Definition | Not to be confused with |
|---|---|---|
| **node** | A drawn box with a label, a class, and zero or more ports. The unit that groups contain and links connect *through*. | *device* (network profile alias), *component* (architecture alias) |
| **port** | A named or anonymous attachment point on a node's **side**. Every link end attaches to a port; a link never attaches to a node directly. Named ports render (the pill); anonymous ports have no geometry and draw no pill, and a routed link end on one draws a dot in the link stroke unless `render.anonymousPortMarker: none`. A port may carry a **class**: a profile *role* (`uplink`, `peer`, …) paints the pill and earns a legend row; a *status* (`up`, `down`, …) paints its stroke (`admin-down` also greys fill and text) or fades it. | *interface* (network alias), *terminal* (electrical alias) |
| **side** | One of `top`, `right`, `bottom`, `left`. Each port has exactly one side, assigned by the engine from the peer's position unless the author fixes it. | |
| **lateral side** | `left` or `right`. A **lateral port** is a port on a lateral side. | a *lateral link* (a flank-to-tier link) |
| **natural side** | The side stages 2 and 5 give a port when no side hint and no author `side:` applies. A hinted port records it as `naturalSide`. The mesh-bus edge, the ADR-0011 title edge and the ELK input read it. | the hinted `side` |
| **side hint** | An engine-chosen lateral side for one port, measured on a placed model and applied at stage 2 of the next placement run (ADR-0022, `docs/design/side-faces.md`). It ranks below an author `side:` and above the stage-2 rule, and is never written in the YAML. The layout JSON records `sideHint: true` and `naturalSide` on the port. | an author `side:` |
| **lane hint** | A side hint that is for the routed L through a side lane (`docs/design/side-faces.md`, Section 19.12). The port carries `laneHint: true` with `sideHint`. `chordKind` gives no chord to its link, so 7a reserves the lane. | a chord hint (a side hint with no `laneHint`) |
| **planned bends** | The bends a link will have, read from placement claims at the end of 7e. A lower bound for a routed link that stage 8 routes. | the bends of the routed path |
| **side lane** | A lane owned by a link with a lateral port on a routed end, through that end's own sub-tier band, from the band edge to the port's y. It stands outside the end's frame, on the side the port faces. | a transit **lane** |
| **side run** | The horizontal fixed segment from a side lane's x to the lateral port's face, at the port's y. | a *stem* |
| **link** | A connection between two ports. Has a **class** (which decides its *family*) and optionally a **route** override. | *edge* (graph-theory word; avoid), *connection* |
| **group** | A labelled container holding nodes. A node belongs to exactly one group. A group has a **tier**, is a **flank**, has a parent group, or is a **canton**, and has a **shape**. | *location* (d3-fd's word), *zone*, *area* |
| **tier** | An integer ordering rank on a group giving its row in the top-to-bottom hierarchy. Tier 0 is the top. Inferred from node classes by the profile when omitted; an explicit `tier:` always wins over class inference. Effective tier bands are compact after normalisation while preserving explicit-rank order. A document tier expands into one or more **sub-tiers** in stage 1; every stage after it reads sub-tiers. | *layer* (reserved for OSI/link-class layers) |
| **anchor** | Of a group: a member with a routed link to the tier above, or, when no member has one, a member with a routed link to the tier below. Anchors take rank 0, or the last rank when they link to the tier below. A group with no anchor has one rank. | *anchor tier*; a link's *anchor* point |
| **peer link** | A routed link inside a group whose two ends are of equal depth (breadth-first distance from the anchors over the group's routed links), or whose two ports are both fixed to `left` and `right`. It never lengthens a rank path. The node class plays no part. | the `peer` port role |
| **rank** | An integer ordering of a group's members from the top of the group: the breadth-first depth from the anchors over the routed links inside the group, before a child span moves a member. A leaf child moves none: the parent members of its ranks stand beside it. Rank 0 holds the members that link to the tier above. A group with no anchor has one rank. | *tier* (orders groups, not members) |
| **rank cell** | The layout group that holds the members of one rank of one document group (`G#r`). A cell is a `row` group to every stage. It has its own sub-tier, no label, no padding of its own (the frame margin is held in the first and last cell; edges between cells hold 0) and no frame. | *frame* |
| **feed order** | The order a rank cell, or a row of child frames beside each other in a frame, takes from its feeds: each unit stands at the mean position of the far ends of its routed links in the one row directly above (downward feeds only). Feed order beats declaration order; a tie keeps the order ELK gave a cell and the declaration order of a frame row; two neighbours a peer link joins stay together. Decided in stage 4 and stored as a `rowOrder` reservation with its premise, the feeding row and its order (architecture-2 ticket 25). Cantons and free rows are not ordered by it. `layout.feedOrder: false` switches it off. | *corridor order* (free rows, ticket 17); *overlay order* |
| **node content** | How a node's icon, title and description sit in its body: `stacked` (default), one centred column; `card`, the icon tile left and the title and the description as one left-aligned block right of it (snack-theme ticket 159). The document field `layout: { nodeContent: card \| stacked }` picks it, and it is a layout input: it changes node sizes in stage 3, unlike `theme:`. One resolver (`resolveNodeContentStyle`) decides, in this order: a node of a `bar` group is `stacked`; else a profile class that states a style; else the document's `nodeContent`. | *theme* (paint only) |
| **width budget** | The positive finite document field `layout.maxWidth`, in published canvas pixels. Above it, placement tries eligible rows widest first. It is an operational input, removed from the echoed document so an already-fitting sheet keeps byte-identical normal output. An absent field takes the original pipeline path. | node size or a scale factor |
| **stagger** | A reserved two-line arrangement of a row of at least three nodes whose routed links all leave through one horizontal face. Feed order stays in x; odd members stand away from the feeds, below for upward links and above for downward links. Stage 5 records the order, face, the centre pitch of each gap and the line step in `staggerRows`; a gap between the members of two parents also holds both parents a row gap apart. It seats feeding faces, fits the frames and bands, and proves each drop straight (far end on the face over the member, a clear vertical, the parent port over the member, the parents centred on the row) or refuses the row by name. Without a budget, stage 5 of the first placement run chooses itself, only on a sheet wider than tall and only toward square, and records `groupArrangements` (ticket 51); an authored `shape` keeps the group as written; `layout.autoArrange: false` keeps every row. Publication and restore preserve the record and clear vertical corridors. A width-budget trial publishes only when narrower, all G1-G9 pass, no link is removed, and staggered members retain straight vertical drops. A missed budget names `WIDTH_BUDGET_UNMET` on the narrowest valid result tried (ADR-0024, tickets 166 and 51). | a grid column |
| **column arrangement** | A group whose members each have one plain routed lateral link to the one node of the group beside it stands one member on each line, centred on one x, one centre pitch apart; the facing node's face takes that pitch, so every link is level and straight and the links keep the order of their ports. Either reading: a flank whose members link to its tier, or a tier group whose members link to its flank. Stage 5 of the first placement run decides it on final sides and records `column` in `groupArrangements` (ticket 52); an authored `shape` and `layout.autoArrange: false` keep the row. The author does not write it, and the group keeps its `shape`. | a grid column (a corridor), a canton column, a grid of one column |
| **sub-tier** | One entry of the dense tier list the layout runs on. Document tier `t` expands to `R(t)` sub-tiers, where `R(t)` is the largest rank count among the groups of tier `t`. Every stage that reads `group.tier` reads a sub-tier. | *tier* (the document's own ordering) |
| **frame** | The drawn box of a document group, derived after placement the way tier bands are: the outermost body of its cells plus 20 px per side, plus the label band, held in the first and last cell. A **child frame** is drawn inside its parent's frame. The frame is the ADR-0013 obstacle and the ADR-0011 title owner. A foreign link's lane stands outside the frame, at one x for all its sub-tiers. A link that ends inside the frame may transit it, and the frame grows to hold its lane. A **member frame** is drawn inside its **canton frame**; a member with one rank, or a `row` member, is a frame of one cell. | *rank cell* |
| **column** | A frame's box plus 20 px slack on each side. The wall centring and the overlay sweeps read. Siblings of one tier are disjoint columns a band gap apart, packed anchor tier first, with each axis on the mean x of its routed feeds. Centring spends the slack, and never leaves less than a band gap between frame boxes. A canton is one column across its tiers: its members stand inside it, on distinct sub-tiers centred on its axis, and members that share a sub-tier stand beside each other in declaration order, 40 px apart for a pair. | *grid* column (a corridor inside one `grid` group) |
| **canton** | A group whose **members** are tier groups of consecutive tiers. It has no tier, no nodes, no shape and no flank, and it is not a member of another canton. It is one top-level frame unit to placement (a **canton column**) and is drawn as a **canton frame**. | *region* (the space between two tiers); *child group* (a rank span inside one tier group) |
| **member** (of a canton) | A tier group that names the canton in `canton:`. A member keeps its tier and its children. A member is a frame, of one cell when it has one rank. | *node* (a member of a group) |
| **aligned extent** | The box a canton member just above the anchor tier takes once its ports stand over their feeds in the anchor row of its canton, with its end-port insets and side-face pills; the centre rule records it (`alignedExtents`), and the member may stand past the canton wall up to it. A member with a feed from outside its canton, or a transit feed, has none (architecture-2 ticket 31). | the *canton column* (the frame box and slack) |
| **canton column** | The canton frame's box plus 20 px slack on each side, derived off the member boxes as they stand, as every column is. Members stand inside it; every other unit stands outside it. Sibling canton columns are disjoint, a band gap apart. A straight link outranks the band-gap close-up: when closing a canton up would bend a straight link, the gap may stay open (user, 2026-10-04). The wall of a member is the canton frame box less the 20 px margin, not the column: a member that spent the slack would grow the box by it at every replay. A member just above the anchor tier may stand past the wall up to the aligned extent it reserved in placement (`alignedExtents`, architecture-2 ticket 31). | *column* (one tier group's frame) |
| **parent spread** | The move of a parent below the anchor tier whose fed bottom ports stand closer than the top ports of its children: the centre rule puts those ports at the spacing of the children once, before its first step, grows the body by the deficit within `ALIGNMENT_MAX_GROWTH` and the window of its tier, and moves its row neighbours apart by the same amount; it records the decision (`parentSpreads`). A child that another parent also feeds (a complete block) is skipped (architecture-2 ticket 32, Q120). | the *aligned extent* (above the anchor tier, the child side grows) |
| **canton frame** | The drawn box of a canton, derived after placement: the union of its member frames grown by group padding, plus the label band on the ADR-0011 title edge. It is an ADR-0013 obstacle and an ADR-0011 title owner. It spans the tier gaps between its tiers. | *frame* (one tier group's) |
| **ranked** | The default group shape. A ranked group with one rank is a `row` in every respect. | `grid` (explicit) |
| **flank** | A group placed *beside* a tier rather than in it: `align: left` or `align: right`. Its links to the tier are lateral. A flank has a **primary peer** — the tier node it shares the most links with. A flank, or the tier group beside it, may stand as a **column arrangement**. | a tier member with `position` hints |
| **shape** (of a group) | How the group arranges its nodes: `ranked` (default), `row`, `bar`, `grid`, `ring`, `free`. M1 ships `ranked` (default), `row`, `bar` and `grid`. | *layout algorithm* |
| **grid** | An explicit shape; `ranked` is the default. A group shape that packs its nodes into shared columns and stacked rows. **A column is a corridor** — a node's downward link drops through whatever its column holds below it — so a column holds at most one node that exits downward and at most one that exits upward, and the column count is bounded below by the larger of those two counts — by the node count where any node exits **both** ways, since that node needs the first row and the last at once. Within that bound it is the count whose **stage-4** box comes closest to square, ties to the fewer columns, measured on the ranked arrangement the grid will really pack; stage 5 re-lays the same count out at final sizes, so the published box is near square and not square. A group whose nodes all exit one way, or that holds one node exiting both ways, therefore takes one row, which is the `row` shape. Rows stand a **band gap** apart, because a bottom port above the last row leaves the group past every row below it. A node whose links leave upward takes the first row and one whose links leave downward the last; a flank's primary peer takes the outer end of its own row. One grid group anywhere re-packs every tier and re-stacks every band, so the shape cannot be adopted group by group without re-reading the sheet. A group that holds both ends of a **bundle** stands each such bundle vertically: the bundle's two ends in one column and adjacent rows (a **chain**), seated before the rows are stacked, with the members on `bottom` (upper end) and `top` (lower end). It declines the shape, and is a `row` to every rule, only where no chain can be seated (`GROUP_SHAPE_DECLINED` names the reason: `authored-side`, `branch`, `cycle`, `exits`, `rows`). Where an arrangement *can* answer, it does rather than refusing: a count that would put in **one column** two nodes joined by a routed link whose two ports the author fixed to `top` is not a candidate, because nodes of one column overlap in x, so the lower one's `top` stem points into the upper one's body and the upper one's port is on the far side of it, above the first row where only the group's own padding lies. Different **rows** are not the fault, different **columns** are not a fault, and `bottom`/`bottom` is measured to publish in the arrangement `top`/`top` fails in — below the last row lie the group padding and the tier gap, and above the first row there is neither. | a portrait `row` |
| **bar** | A group shape where each node renders as a horizontal bar spanning its attached ports' x-range; links onto a bar are vertical drops, ports ordered by source x. Bars may stack; a drop may cross an upper bar to reach a lower one. | a wide `row` node |
| **region** | The space between two adjacent tiers, or between a flank and its tier. Routing strategy is chosen per region by what is on each side. | *group* |
| **lane** | A reserved vertical corridor (`laneW` = pill width + gap ≈ 34 px), in the margin beside a group, for one link transiting a tier it does not terminate in. A lane has an **owner**; it is an obstacle to every link, its owner included. The owner passes through it only as the collinear run the lane reserved, never as a routed gap. Reserved before anything is pinned. A **riser lane** is owned by a joined **mesh bus**, not a link: it holds the riser's x through one crossed sub-tier and has no routed run (Q107). | *channel*; the 16 px **member gap** inside a bundle |
| **anchor tier** | The tier with the most main-tier nodes, including bars and excluding flank nodes (ties: lowest effective tier index). Groups below it are centred under their feeds; groups above it are centred over their children. Below it a parent may spread its ports over its children once before the steps (*parent spread*). | |
| **junction** | A branch point in a tree of shared runs at one port. Source and target incidence use the same outward tree. Only declared shared runs are exempt from the overlap gate. It is model geometry reserved during placement, never a runtime `JunctionRef`: stage 8 stitches the reserved run back unchanged and routes only the gap beyond its terminal. | *bundle* |
| **band** | Reserved horizontal space: a **tier band** (the vertical extent a tier occupies) or a **label band** (space inside a group's top padding reserved for its label). | |
| **part** | The path of one routed link inside one tier gap, from one end to the other. Every part of a gap is planned in placement (ADR-0021, `docs/design/tier-gap-rows.md`), except a residual one. A held **routed chord** is not a part. An end is a **tip** (a port's stem tip, where the stem plan puts it) or a **mouth** (a lane's approach point, one router stem inside the gap boundary). | *piece* (`RoutePiece`, one stitched stretch of a path), *segment* |
| **drop** | A part whose two ends stand less than one run clearance apart in x. It takes one vertical, with a jog where the ends differ. | a bar drop (a link onto a bar); a *column* |
| **stepped part** | Any part that is not a drop: an upper leg, a run on its own row, and a lower leg, each on its end's x. | |
| **Z part** | A stepped part with two rows and a **middle drop** between them; used only where one row is impossible (a cycle among the rows). The middle drop stands on the widest interval `k` clear of every other leg and drop. | |
| **residual part** | A part the plan declines (`spans-two-gaps`, `lateral-port`, `u-turn`, `faces-away`, `off-boundary`, `crosses-lane`, `crosses-shared-run`, `leg-blocked`, `row-cycle`). The router lays it among the reserved parts; it is named `TIER_GAP_PART_RESIDUAL` (`TIER_GAP_ROW_CYCLE` for a cycle), crosses the planned rows of its gap, and is granted the cover of a planned vertical that stands within a run clearance of its span. | a removed link |
| **multiplicity label** | The measured count drawn beside one counted merge trunk, owned by the trunk's bundle. Stage 9 places exactly one per `mergeRuns` record; it clears every routed member segment and is never shortened. | a **link label** (one authored label, owned by its link, exempt only from its own supporting segment) |
| **supporting segment** | The one path segment a visible link label was finally measured against, persisted on the label. Its clearance zone is the only thing G3 exempts: text across the segment itself is still a hit, and a stale or absent reference exempts nothing. | the link's other segments |
| **skeleton** | The tier/group placement produced by ELK before region rules run. Lateral (flank↔tier) links are **withheld** from the skeleton so flanks land beside their tier. | *layout* (the whole result) |
| **bundle** | Two or more routed links between the same pair of nodes, routed through a channel and fanned to ports. The **channel** is the space between the two endpoint **bodies**, measured along the bundle's own normal; it exists only where the two bodies stand beside each other across that normal, in that order, and nothing stands between them — a node beside the channel but not in it is no obstacle, so adjacency is not the predicate. A grid that holds **both** ends of a bundle turns it to `bottom`/`top` and stacks its ends in one column; where it cannot, it declines the shape (`GROUP_SHAPE_DECLINED`, with a reason) and is a `row` to every rule. The case that still needs the refusal is incomplete by construction — a bundle between a **flank** and one node of a stacked group has no group holding both ends, and stacks its reserved blocks across the rows regardless. Its **envelope** reserves the swept geometry, including stroke width. Parallel members cross once for each strict endpoint-order inversion; shared-port ties count as zero. A heavily inverted bundle draws **straight members** (stem, one diagonal, stem) instead of the orthogonal staircase, when the existing geometry holds the member gap between every pair of member segments G6 measures (ADR-0017). Engine order minimizes avoidable inversions where incidence and reservations permit it. Selected `route: merge` members share counted trunks; other members remain parallel. | *overlay* |
| **routed chord** | The straight technique of a routed link: one segment from one port's face to the other's, at any angle, with no stem. A **frame chord** has both ends in one frame (the same frame, or a parent and its direct child; Q93). A **cross-frame chord** has its ends in two frames or free groups on consecutive document tiers, the upper port on `bottom` or on a lateral side a hint gave it, and the lower on `top` or on a lateral side; it leaves each end frame through the edge its port faces (the bottom or top edge, or the side edge for a lateral port, read per port face), keeps out of every foreign frame and canton box, and may cross any title band: no title refuses a chord, the title is placed last and yields to it (architecture-2 ticket 54; Q108 and ticket 162 refused an axis chord where the title did not fit beside it). A chord between two end faces at 90 degrees (a `top` or `bottom` face and a lateral side) that is at least twice the larger body (the straight-link length limit) and leaves the `top` or `bottom` face 80 degrees or more from its normal makes the link orthogonal, decided before the freeze; a shorter or steeper one, opposite faces and faces on one side keep the chord rules (user, 2026-10-24). A chord is decided in the `rebuildRowPaths` fixed point and frozen at the start of 7f; a refused candidate stays orthogonal. A member of a triggered **direct family** is decided by the family verdict instead (ticket 22, `docs/design/routed-chords.md` Section 15). A member of a **fan family** is decided by the joint admission of its family instead, and crosses foreign frame, group and canton boxes (ticket 40). A held chord reserves no stem, leg, lane or gap row, is no part of the tier-gap plan and no router obstacle; the plan keeps a Z middle drop `k` from it. Spec: `docs/design/routed-chords.md`. | a **straight member** of a bundle (ADR-0017); an overlay chord (not routed) |
| **fan family** | The dashed or dotted routed links of two or more hubs in one tier group to three or more far units (the outermost frame, canton or free group of the far end), on the next document tier above or below, with complete incidence: every hub links to every unit (user rulings Q124 to Q126). Decided once in stage 1 (`fanFamilies`, `link.fanFamily`, `FAN_FAMILY`); a link two families claim declines both. Solid links form no family. Before the freeze one admission per placed model searches the members jointly (`familyVerdict`, at most `FAN_SEARCH_BUDGET` tested configurations per family, then `FAN_SEARCH_TRUNCATED`): the largest set whose chords hold together, then the shorter total length, then the port keys. A straight member is one segment from face to face, a held chord that crosses foreign frame, group and canton boxes; it records the boxes it crosses (`fanAdmissions[].crosses`), and G2 excuses those boxes and no other. A member a body refuses falls back alone, orthogonal and dashed, with a reason. No title refuses or crowds a member: the title is placed last and yields to it (architecture-2 ticket 54). At the freeze a member that passes a sibling fallback's stem falls back (`stem`); the retry of 7f refuses one that a moved part (`crowds`) or a sibling's stem (`stem`) still meets, and a chord that a refused member's legs then refuse names its own refusal. After `DIRECT_RETRIES` the rest stay straight and `FAN_MEMBER_CROWDED` names them. The rows of the tier-gap plan keep the clearance from a straight member, or cross it strictly, lowered at most `SLANT_LOWERING_KEEPS` clearances (`TIER_GAP_SLANT_LIMIT` names a row that keeps its seat). Two members of one family cross faintly: 0.09 each (*salience*), counted in the Xf column and not in X. A fan family is routed, not overlay: it stands in the routed layer and keeps every clearance gate. A member of a direct family is no member. Spec: `docs/design/routed-chords.md` Section 16. | *overlay* (unrouted, gate-exempt; looks the same in a PNG); *direct family*; *bundle* |
| **direct family** | The routed links from one source node to the facing row (or node) across one tier gap, between two `row` groups on adjacent occupied sub-tiers (architecture-2 ticket 22, slice 1: no bundle, label or shared port). When their orthogonal drawing would cross more than once, the members are routed chords decided together, at any angle, in peer order with no crossing inside the fan; a member that cannot is orthogonal with a reason. Decided once at the start of 7f and recorded (`directFamilies`). Spec: `docs/design/routed-chords.md` Section 15. | a **bundle** (two or more links between one pair of nodes) |
| **overlay** | A link family drawn thin, translucent and *unrouted* on its own layer beneath routed links. Used for flow-class links (e.g. NTP sync) and signal links (a satellite or GPS feed, not a cable; drawn dashed; Q104). Exempt from clearance gates. Its path is not routed but **derived**, and the rule is **straight by default, orthogonal by exception, and the exception is a node in the way** (maintainer, 2026-09-16): **one straight segment from one port's outward face to the other's**, at whatever angle, and nothing else — no stub (*"no point in stub then"*, maintainer, 2026-09-16) — unless the segment **fails to leave a port outward** or enters a **node body or a foreign port pill**, and then it is the orthogonal path that leaves each face outward by the **overlay port clearance** and goes round the shapes it would otherwise cross. **Two overlay detours never share a track** (ticket 23): the layer is read once, and a detour whose run lies on another overlay path's run within the **overlay track pitch** moves that run out by whole pitches, or takes another way round with the same bends. *Leaving outward* is the branch's own condition: at each end the segment's direction out of that end may not point back along the port's own outward normal. **An overlay line never rides along a face or a foreign pill** (architecture-2 ticket 34, user 2026-10-25, reversing "level counts as leaving" of 2026-09-16): a segment that runs along an axis and lies within one stroke width of a face of any body or pill, its own included, over a stretch of that face, is not straight-clear, so two ports level on one side take a U whose run stands one **overlay port clearance** beyond the furthest pill tip or body edge across its span (`ridesAFace`). A segment that passes a face further off than one stroke width stays straight; keeping the clearance from every shape passed is ticket 41. The segment that leaves its own pill perpendicular to the face meets that pill and its body only at its end point, so it is exempt; an angled segment keeps the outward test and `crosses` alone. A port facing **away** from its partner does not, and takes the orthogonal branch, because a line leaving a port inward runs back under that port's own pill and the mask would cut it away from its endpoint mark. Because that condition holds, a link's **own two pills** cannot be entered by its own straight segment and are not tested by `crosses` — its node bodies are; riding along them is the face test's to refuse. Nothing else blocks it: not another overlay line, not a group box, a lane, a routed path or a label. A **group title** is one of these labels: a chord may lie under a group title or a canton title alike, and moves neither the chord nor the title. The title keeps readable through its halo, an outline in the colour behind it under its glyphs; the overlay mask no longer cuts a title out (ticket 162, which replaced the cutout of ticket 60). The mask still cuts the line out of a pill; a link label cuts its own line, and a title or a foreign link label cuts an overlay line only where an orthogonal run of it meets the text. Placement's job is to position nodes so that as many overlay links as possible take the straight branch. **Architecture ticket 15, phase 7 (the user's ruling Q1, an offer):** where a routed chord would not stand (`overlayChordAdmitted`: no cell, group box or frame that holds neither end on the chord, each end box left through the edge its port faces, no body or pill on it) and the baseline bends the link, a planned **course** on side faces is offered, as for a routed link: a perimeter lane of the overlay layer in the margin, padding rows, side runs into lateral faces. The faces come from the course (*"choose the side from which routing occurs"*), the lane is reserved in placement and `overlayPath` draws the course from it; the overlay layer owns no clearance gate, so the brackets of one margin nest by span and cross no other bracket. The courses are kept only when the published result is not worse by `unified` (bent links over both layers, then turns, then crossings); the round shares `MAX_RERUNS` with the other rounds and takes only a re-run they left. One opt-in exception: with `layout: { overlayOverBodies: true }` stage 8 draws the straight segment over node bodies that are the only blocker (a foreign pill or an own end body still bends it), and states `OVERLAY_OVER_BODY`; placement does not know the setting (ticket 152). | *bundle*, the **stub** technique (a different thing), a **fan family** (routed and gated; it looks the same in a PNG) |

## Invariants

1. **Links attach to ports, never to nodes.** A link written to a bare node gets an anonymous port.
2. **A node has exactly one group.** A group may have one parent group; a child group has no tier of its own and is a span of whole ranks inside its parent. A tier group may belong to one canton. A canton holds tier groups of consecutive tiers and belongs to no canton.
3. **Node size is derived from its content and its ports:** the larger of the measured label/description/icon bounds, the author's `size:` floor, and per-side port counts × the measured pitch of that side. Never shrunk to fit.
4. **Port topology freezes before paths:** identity, count, side and author `order:` are fixed after the two side phases. Engine-selected order may still change where bar and bundle rules require it, including compatible primary-bundle order during flank alignment, and in stage 7a where a lane fixes the planned first turn of a link (the turn order of `docs/design/turn-order.md`, only in a run that carries it). Bundle rules may grow endpoint pitch and capacity, repack rows, re-level blocks and reserve crossing space before paths. Fixed lane x and owners remain immutable. Placement may grow or move geometry only through its declared rules; it never shrinks a node below its current content or author floor. Final placement freezes after all region rules.
5. **Meaning before geometry, space before use:** which technique a link gets is decided from the document (stage 1); lanes, bands, bundle rows and bar spans are reserved during placement, not discovered during routing.
6. **Every fixed path is an obstacle** for everything routed after it. All paths are validated together at the end.
7. **Region rules are the router for regular tiered diagrams.** libavoid routes only what the rules do not claim.
8. **The tier contract survives at any size:** ELK partitioning is always attempted; on exception **or deadline**, one ELK run per tier band, stacked; bands are validated after either path (ADR-0006).
9. **Nothing is styled by value in YAML.** Nodes, links and groups carry `class`; a profile theme and an optional `css:` block do the rest.
10. **The layout JSON is a first-class output.** SVG is one renderer of it; `score` reads it directly.
11. **A diagonal may cross text** (ADR-0023, owner 2026-10-31). A straight segment at least 10 degrees from both axes (`DIAGONAL_MIN_DEGREES`; an overlay chord, a routed chord, a straight member) may cross a group title or a link's own label; one predicate says so (`diagonalMayCross`), and no stage refuses, bends, moves or counts the diagonal for it. Node bodies, the labels inside them, port pills, multiplicity and bus labels keep their rules, as do orthogonal segments and the label-vs-label and label-vs-node rules. A segment nearer an axis keeps the orthogonal rules. Every text outside node bodies carries a **halo**: an outline in the colour behind it, painted under its glyphs. A label's mask cuts its own line only; a title or a foreign label cuts an overlay line only where an orthogonal run meets it.
